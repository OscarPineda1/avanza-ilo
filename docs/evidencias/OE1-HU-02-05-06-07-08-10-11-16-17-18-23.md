## Resultado central reproducible

El ejemplo es **sintético**, exactamente como lo declara la página 9 del informe. No representa un horario real de Ilo.

```text
Ruta: A → B → C → D
Tiempo A→C: 5 min
Salidas: 07:00, 07:10, 07:20
Consulta en C: 07:12
Esperado y obtenido: próxima llegada 07:15; ETA 3 min
```

Se reproduce con `npm run demo:arrival`. El motor considera la salida 07:10 aunque ocurrió antes de la consulta. También prueba llegada exacta (`0 min`), consulta anterior al servicio, última unidad todavía en recorrido, cierre de servicio, sentido inalcanzable y datos inválidos.

## Condición honesta del dato real

Las fichas actuales sí declaran horario de operación y frecuencia, pero **no acreditan una fase de despacho programada u observada**. Por eso la app muestra `Espera promedio estimada` mediante `frecuencia ÷ 2`; no muestra una hora de próxima unidad ni simula GPS. El antiguo texto `Margen ±5 min` fue retirado porque aún no existe contraste de campo que lo sustente.

El motor de HU-17 está funcional y probado con reloj controlado. Para activarlo con datos reales, Oscar debe aportar observaciones de despacho y tiempos por franja, separando calibración y prueba. Hasta entonces HU-17/HU-18 tienen capacidad técnica implementada, pero su aceptación con datos reales permanece pendiente; este repositorio no fabrica esas observaciones.

El perfil espacial actual `ilo-dia-base-v1` usa 25 km/h como supuesto técnico provisional y queda etiquetado como `assumption`. No se afirma mejora antes/después ni adaptación automática al tráfico.

## Rendimiento y código retirado

- El cálculo del flujo de usuario corre en la Function HTTPS. El cliente no importa el motor ETA local.
- Dijkstra usa una cola de prioridad y pasa de la búsqueda cuadrática anterior a `O((V+E) log V)`; además reconstruye el camino mínimo.
- La geometría de visualización se simplifica y cachea sin alterar las 3033 coordenadas usadas por el modelo.
- Los marcadores dejan de rastrear cambios después de su montaje inicial.
- Se retiraron Firebase del bundle móvil, la consulta remota duplicada, dos pantallas sin navegación real y la configuración de backend no desplegada.
- `.env` dejó de estar versionado y las claves de Maps ya no tienen valores incrustados en el código.

- No hay transbordos ni conexiones entre rutas.
- Las referencias matemáticas no se anuncian como paraderos oficiales.
